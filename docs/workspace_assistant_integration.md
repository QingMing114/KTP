分析提醒（2026-10-12）：整个左侧分析面板在关键状态变化时短暂泛光，青色表示定位或执行、绿色表示完成、黄色表示需要确认/查看说明、红色表示失败。每次以2秒周期缓动3次，6秒后停止；普通轮询、进度百分比和文字变化不重新触发。新影像或任务配置由助手/异步加载更新时也会提示，用户正在操作左侧配置时不重复提醒。恢复旧任务首个快照保持安静，后续真实状态变化正常提醒。提醒携带对应工作流 ID；查看历史任务时后台当前任务的变化不会强制切换视图，可点击提醒定位正确任务。用户点击处理或确认已看到后取消高亮；未读提示保留在可见入口，窄屏不会自动打开侧栏打断聊天。支持 prefers-reduced-motion，此时仅静态高亮。提醒只改变展示状态，不修改任务参数、选区或执行状态。

## 需求与现有设计的关系

目标是让地图工作台助手理解当前操作上下文，以自然语言推荐和执行专业任务，并在现有 mock 卡片的视觉结构中展示分析步骤、参数、进度和结果。本文将“mock 卡片”理解为地图工作台已有的卡片样式和演示交互，而不是要求真实任务使用模拟算法结果。

原始开发文档 `memory/firstread/定量遥感大模型训练推理与知识编辑技术开发文档.md` 已提出自然语言任务理解、专业工具调用、统一执行内核和流式反馈。因此本需求符合原始方向，主要补齐地图交互与执行系统之间的连接。

当前产品协议存在一处需要调整的边界：`canonical_product_protocol.md` 将内部 planner、delegation 和 tool phases 归为 debug details；`frontend_integration_standard.md` 禁止前端依赖内部工具和 trace 结构。应新增稳定的产品层计划、参数与动作表示，让普通用户可以理解任务，而底层 trace 仍保留在调试接口。不能直接把 `/v2` 调试事件变成地图工作台的长期接口。

| 能力 | 当前源码状态 | 本次需求 |
| --- | --- | --- |
| 对话上下文 | 工作台只提交消息并继承最新对话，没有提交当前地图状态 | 每轮同步当前 AOI、影像、工作流和运行模式 |
| 助手展示 | SSE 提取文本，最终 Run 的 parts 也被转为文本 | 保留结构化计划、参数、动作与关联任务 |
| 卡片触发 | 页面依据 AOI 和影像 stage 展示固定卡片 | 助手可以根据请求输出任务建议或补充输入卡片 |
| 任务启动 | 用户点击多选卡片，页面调用统一工作流接口 | 明确的执行指令可通过助手启动同一工作流 |
| 分析过程 | 工作流已有步骤、状态、进度和依赖；演示 LAI 有固定进度卡片 | 增加规划说明与实际生效参数，不以进度百分比猜测真实阶段 |
| 演示与实时 | 页面已有两种模式，但助手请求未携带模式 | 助手与卡片始终显示一致的模式和执行状态 |

## 用户交互目标

1. 用户框选区域，询问“接下来我应该干嘛”。助手识别已存在的 AOI；未选影像时展示搜索影像动作，有影像时展示任务建议及多选卡片。建议本身不启动计算。
2. 用户选择影像后询问“这里能做哪些分析”。助手依据可用能力给出 LAI、作物识别、长势等任务卡片，说明用途、依赖和缺失输入。
3. 用户说“执行 LAI 反演和作物识别”。输入完整时，助手直接创建一个统一工作流，立即展示任务 ID、参数和真实状态；无需再次点击“执行”。用户点击卡片按钮也走同一个执行入口。
4. 用户说“先做 LAI，再估产”。服务端展开依赖，区分用户选择与自动添加的任务。产量缺少核验数据时展示缺项，已有可执行步骤可以继续，不伪造产量结果。
5. 用户说“只做 LAI”时，修改尚未执行的任务草案；已有运行任务不被这句话隐式撤销，助手应说明其状态，必要时询问用户所指的任务。
6. 用户询问“为什么这样配置”。助手基于参数快照、算法说明和实际数据解释配置，不能把建议值说成已生效参数。
7. 任务完成后，在同一时间线中提供结果卡片、地图图层和报告。刷新可恢复工作流及关联对话；切换选区或影像后明确历史任务所用输入。

“执行”“开始运行”等明确指令以及执行按钮均可作为启动依据。只有缺少必要输入、任务指代不明确或上下文已变化时才要求补充信息。普通建议和能力咨询不启动任务。

## 产品层数据契约（拟新增）

所有新增字段、事件和动作均需在 manifest 中声明能力，并保留旧客户端兼容性。以下为协议设计，不是现有 API 保证。

### 工作台上下文

扩展 Submission 的 `context`，增加可选 `workspace` 快照：

```json
{
  "context": {
    "inherit": "latest",
    "workspace": {
      "workspace_id": "ws_example",
      "revision": 12,
      "execution_mode": "live",
      "farm_id": "farm_example",
      "aoi": { "geometry": { "type": "Polygon", "coordinates": [] }, "source": "drawn" },
      "imagery_item_id": "sentinel_item_example",
      "imagery_snapshot": {},
      "active_workflow_id": null,
      "draft_task_ids": ["lai", "crop"]
    }
  }
}
```

示例中的空几何和空影像对象仅表示结构；真实请求必须使用有效 GeoJSON 和服务端可验证的影像快照。执行模式使用 `demo | live`，缺失值用 null 或省略表示，不在提示词中猜测。

当前地图快照优先于历史对话继承。revision 在 AOI、影像、任务草案或执行模式变更时递增；服务端保存与动作绑定的已验证快照，并在提交前检查其是否仍有效。客户端变更需同步服务端，执行前再次检查，不能仅依靠模型回传的 revision。服务端重新核验区域、面积、影像签名、工作流所有者和能力可用性。

首期仅在明确处于工作台的请求中启用地图动作；普通 Chat 没有 workspace 上下文时沿用现有路径，不能误用上次地图选区。

### 助手结构化内容

扩展 `assistant.parts`，支持以下产品层内容；旧客户端忽略未知类型并继续显示 summary：

| 拟新增 part 类型 | 用途 | 必须包含的信息 |
| --- | --- | --- |
| `analysis_plan` | 可折叠分析步骤和简要依据 | plan_id、任务与依赖、缺项、所用上下文版本 |
| `parameter_set` | 参数配置卡片 | 任务、参数名/值/单位、来源、是否可编辑、草案或生效状态 |
| `action_card` | 搜索、选择影像、选择任务、补充输入等操作 | action_id、动作类型、标题、可执行状态、不可执行原因 |
| `workflow_reference` | 绑定已经创建的专业任务 | workflow_id、plan_id、执行模式、状态、输入快照引用 |

模型可以提出结构化意图，但前端只渲染服务端验证后的卡片。动作限制为预定义类型，例如 `search_imagery`、`select_imagery`、`configure_tasks`、`start_workflow`、`retry_step`、`update_yield_inputs`、`open_report`。不得从自由文本解析 API 地址、执行任意脚本或自动点击按钮。

“思考过程”展示已公开的任务计划、选择依据、输入检查和执行反馈；可以使用“分析过程”作为标题。无需依赖或保存模型原始内部推理。真实流程的进度和失败必须来自执行服务；演示数据必须明确标为演示。

### 参数快照

参数应区分“建议配置”“待提交配置”“实际生效配置”，来源包括用户指定、服务端默认和算法固定值。只能修改服务端公布并验证过的参数；暂不支持修改的参数显示为只读。

当前统一工作流请求尚未提供通用 LAI 参数入口，执行器中影像准备分辨率为固定 20 m。不能因为卡片显示了参数，就宣称已支持配置 LUT 数量、反演范围或求解方法。实现需先核对真实算法与单任务接口，再决定扩展哪些字段。实际生效参数应由服务端标准化后持久化，执行器与报告读取同一份快照。

首期卡片展示选区、影像 ID/观测日期、PROSAIL 方法说明、实际分辨率、任务选择和依赖；算法版本及其他参数只有在后端能提供可追溯值时才展示。阶段进度不能冒充算法配置。

### 事件与生命周期

建议新增 `assistant.part.updated`、`action.updated`、`workflow.linked` 产品事件；已有工作流事件继续用于步骤状态和进度。事件携带稳定 ID、关联的 Submission/Run/Workflow 和顺序号，支持去重、断线恢复和持久化回放。

对话 Run 的完成表示该轮回答或动作处理结束，不表示关联的长时工作流完成。助手取消回答也不能被描述为专业任务已停止；专业任务取消应在真实后端能力提供后再开放。助手显示的“已启动”必须有服务端返回的 workflow_id。

## 执行设计

采用“意图理解 → 校验计划 → 公共执行服务 → 工作流事件 → 卡片与地图”的闭环。

将现有工作流创建、影像搜索和必要的状态校验整理为公共应用服务：HTTP 路由与 Agent 工具调用相同服务。计算继续由现有工作流执行器驱动，避免助手另建一套 LAI 或作物识别逻辑。

1. 服务端把当前快照与真实能力交给助手，助手输出咨询、建议、配置或执行意图。
2. 服务端依据结构化 schema、能力和上下文验证意图，展开 `growth → lai`、`yield/potential → crop + lai` 等已有依赖，返回可展示计划。
3. 仅明确启动的指令或按钮提交计划；对含糊输入先给出草案或补充输入卡片。
4. Agent 启动与卡片启动通过同一公共服务使用同一幂等规则。自然语言启动应在服务端执行；前端收到 workflow_reference 后绑定任务，而不是收到卡片便再创建一次。
5. 创建结果与 action_id、plan_id、conversation_id、run_id、输入 revision 关联并持久化。相同 action_id 的重试、SSE 重放、重复点击和断线补发只能得到同一工作流；重新执行则产生新的动作 ID。
6. AOI 或影像变化使旧草案失效；历史任务保留原输入。已经进入执行的任务继续基于提交时快照运行，不随地图编辑改变。
7. 前端订阅现有工作流状态，把结果关联到正确任务与图层。新的任务不能覆盖旧任务的输入、报告或结果来源。

幂等保证需要落在持久化存储及事务边界，不能只用按钮禁用或前端 ref。现有文档中的 Submission 幂等保证不等于工作流创建已支持幂等，需单独实现并验收。

会话时间线记录用户消息、助手说明和本轮只读配置快照，以稳定 ID 更新原位置。工作台仅有一张持续更新的“当前分析”卡片，统一承载选片、任务配置、启动、进度和结果；历史任务折叠为只读记录。共用数据 schema、事件归并和展示逻辑，允许 Chat 与地图采用不同配色。

## mock 卡片与实时卡片

保留现有卡片视觉设计，新增可折叠的分析过程和参数区。卡片由类型化数据驱动；demo 使用固定场景数据，live 使用服务端事件与快照，二者共用渲染组件。

demo 中的步骤、配置和结果始终标为演示；不能自动发起真实计算，也不能在真实任务失败后自动切换为演示。切换模式会使未执行草案失效。若某能力在 demo 中未提供，展示其不可用原因。

## 验收场景

- 仅有 AOI 时问下一步：识别当前选区，给出搜索影像卡片，不误报已选影像，不启动计算。
- 已选影像时问可做什么：展示真实能力和任务选择卡片，包含缺项与依赖说明。
- 指令执行 LAI 与作物识别：只产生一个工作流，原始任务为两项，影像准备共享，卡片与地图使用同一 workflow_id。
- 重放事件、重复点击或重试提交：同一动作不产生重复工作流。
- 缺影像时请求执行：展示补充输入卡片，不声称任务启动。
- 输入已有固定参数时展示配置：卡片所示值与执行器、持久化记录及报告一致；不支持的修改返回明确说明。
- 异步回答期间切换区域或影像：旧草案失效，不能在新的区域静默执行；历史结果保留原快照。
- 请求长势或产量：按现有依赖展开；APSIM 缺真实资料时保持 blocked，并列出缺项。
- 真实执行失败：显示真实错误和可用重试，不自动返回 demo 结果。
- 刷新与断线：恢复对应对话、卡片、工作流及进度；对话完成和工作流完成分别展示。
- 取消助手回答：仅停止该轮问答，正确说明后台工作流状态。
- 不同用户与工作区：不能读取或执行其他所有者的计划与工作流；工作台上下文不会污染普通 Chat。

## 实施记录（2026-10-12）

- 工作台每轮携带真实地图快照，并通过 context 接口同步版本；服务端在规划后与创建事务内再次检查，区域/影像变化使旧草案失效。
- 复用已配置模型生成受限意图，输出分析计划、参数卡片、任务动作和工作流引用；普通 Chat 保留原有运行路径。明确执行指令直接启动，咨询和配置不启动。
- 卡片按钮校验其来源 Run、对话、动作和地图输入。按钮中的任务选择可以调整；执行时以当前同步快照校验，原地图输入变化则拒绝旧卡片。
- 自然语言与按钮复用同一创建、影像核验和执行服务。SQLite 事务持久化动作与工作流关联，原子启动声明阻止重复 worker。
